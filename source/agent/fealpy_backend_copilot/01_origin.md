# FEALPy 多后端接口助手的起始需求描述和工作内容

## 一、搭建流程与工作内容
### 1.1 提示词
>如何快速搭建符合下面的需求的智能体。给出具体的流程和每个流程中要做的工作
问题：在新人学习、使用FEALPy多后端（包括numpy、pytorch计算后端）时，常常不知道功能对应的接口是什么，比如创建随机张量，求解范数。如果是直接使用numpy、pytorch，网上有很多公开的资料，或者询问AI大模型也可以知道某个功能的接口是什么。但是由于FEALPy在网上没有很多关于这方面的资料，也没有官方文档，所以新成员想使用某个功能时，查不到接口，或者让本地的大模型扫一篇FEALPy的所有内容，很麻烦，如果没有本地的大模型，问网页版的大模型也一定能回答准确，因为大模型不一定了解FEALPy。
功能需求：
阶段一：智能体能基于用户关于张量的功能需求描述后，返回FEALPy的接口、参数设置，以及对应numpy、pytorch计算后端的原始接口。
阶段一主要是服务于团队的新成员，解决新成员学习和使用FEALPy多后端的难题。
补充的资料：FEALPy最简单的使用示例
from fealpy.backend  import bm
bm.set_backend("numpy")
A = bm.tensor([1,2,3])
bm.set_backend("pytorch")
B = bm.tensor([1,2,3])
print(A, type(A), '\n', B, type(B))

### 1.2 回复：具体的搭建流程和每个阶段要做的工作
搭建这样一个智能体，核心思路是：**先系统性地提取FEALPy的接口信息，构建一个结构化的知识库，再让大模型基于这个知识库来回答问题**。这样既能保证准确性，又能避免每次“扫一遍”整个代码库的麻烦。

下面是具体的搭建流程和每个阶段要做的工作。

### 阶段一：知识库构建（最核心的准备工作）

这个阶段的目标是把FEALPy的接口信息“挖”出来，整理成机器可以理解的结构化数据。

**1. 代码库扫描与接口提取**
- **要做的工作**：遍历FEALPy的源代码，重点提取 `fealpy/backend` 模块下所有 `bm` 对象暴露的公共方法。你需要关注：
    - **方法名称**：如 `tensor`, `norm`, `einsum` 等。
    - **函数签名**：参数名称、默认值、类型提示。
    - **文档字符串**：从docstring中提取功能描述、参数说明和返回值。
    - **代码示例**：如果docstring里有示例，一并提取。
- **产出**：一份JSON或CSV文件，每一行对应一个FEALPy接口，包含 `name`, `signature`, `docstring`, `source` 等字段。

**2. 建立多后端映射关系**
- **要做的工作**：FEALPy的 `bm` 接口遵循Python Array API标准，本质上是对NumPy、PyTorch等后端同名函数的封装。你需要为每个 `bm` 接口建立与各后端原始接口的映射。例如：
    - `bm.tensor` → NumPy: `np.array`, PyTorch: `torch.tensor`
    - `bm.norm` → NumPy: `np.linalg.norm`, PyTorch: `torch.linalg.norm`
    - `bm.einsum` → NumPy: `np.einsum`, PyTorch: `torch.einsum`
- **产出**：一个映射表，可以附加在第一步的JSON文件中，或者单独维护。如果映射关系难以自动提取，可以手动整理一份核心接口的对照表。

**3. 构建向量知识库**
- **要做的工作**：将上一步整理好的接口描述（包括签名和文档字符串）通过一个嵌入模型（如 `text-embedding-3-small` 或开源的 `bge-m3`）转化为向量，存入向量数据库（如Chroma、FAISS或Milvus）。
- **目的**：当用户提问“创建随机张量”时，可以通过语义相似度快速检索到最相关的接口（如 `bm.random.rand` 或 `bm.random.randn`），而不是靠关键词匹配。

### 阶段二：智能体核心逻辑设计

这个阶段定义智能体如何利用知识库来回答问题。

**1. 用户查询理解**
- **要做的工作**：设计一个提示词（Prompt），让大模型首先解析用户的自然语言描述，判断用户意图。例如，用户说“求范数”，模型应识别出核心操作是 `norm`，并询问或推断是哪个轴的范数、是否需要保持维度等参数。
- **产出**：一个清晰的查询意图JSON，包含 `operation`（操作类型）和 `parameters`（参数约束）。

**2. 知识检索**
- **要做的工作**：用上一步的意图向量，在向量数据库中检索最相关的FEALPy接口。可以返回Top-3结果，并附带每个接口的完整信息（签名、描述、映射关系）。
- **关键点**：检索时要确保覆盖到后端差异。例如，如果用户指定了 `pytorch` 后端，检索结果中应优先展示PyTorch的映射接口。

**3. 答案生成与格式化**
- **要做的工作**：将检索到的接口信息作为上下文，连同用户问题一起发给大模型，要求它生成结构化的回答。回答格式建议如下：
    ```
    FEALPy 接口：`bm.tensor`
    参数说明：`data` (array_like), `dtype` (可选), `device` (可选)
    功能描述：将输入数据转换为当前后端（bm）下的张量对象。
    对应后端：
      - NumPy: `numpy.array(data, dtype=None)`
      - PyTorch: `torch.tensor(data, dtype=None, device=None)`
    示例代码：
      import fealpy.backend as bm
      bm.set_backend("numpy")
      A = bm.tensor([1,2,3])
    ```
- **产出**：一个模板化的提示词，强制模型按此格式输出。

### 阶段三：系统实现与集成

这个阶段是把上面的逻辑用代码实现出来，并提供一个用户可用的入口。

**1. 技术选型**
- **开发框架**：推荐使用 `LangChain` 或 `LlamaIndex`，它们内置了检索增强生成（RAG）的流程，可以快速搭建。
- **向量数据库**：Chroma（轻量、易用）或 FAISS（性能好）。
- **大模型**：可以调用OpenAI API，也可以使用本地部署的模型（如Qwen、DeepSeek），如果团队有GPU资源的话。
- **后端服务**：用 `FastAPI` 写一个简单的API接口，或者做成一个 `Gradio` 界面，方便新成员直接对话。

**2. 实现检索增强生成（RAG）流程**
- **要做的工作**：
    1.  用户输入问题。
    2.  用嵌入模型将问题向量化。
    3.  在向量库中检索最相关的接口文档片段。
    4.  将检索结果和问题拼接成一个提示词。
    5.  调用大模型生成回答。
    6.  返回格式化的结果。

**3. 添加多后端识别逻辑**
- **要做的工作**：在检索环节增加一个过滤条件。如果用户明确说了“pytorch后端”，则在检索时优先过滤出包含PyTorch映射的文档片段；如果用户没说，则默认返回所有后端的映射，并注明“可通过 `bm.set_backend()` 切换”。

### 阶段四：测试与迭代

**1. 构建测试用例**
- **要做的工作**：整理一批新成员常问的问题，例如：
    - “如何创建一个随机张量？”
    - “如何计算矩阵的Frobenius范数？”
    - “如何在GPU上创建张量？”
    - “如何对两个张量做爱因斯坦求和？”
- **产出**：测试集，用于评估智能体回答的准确性。

**2. 评估与优化**
- **要做的工作**：对比智能体的回答与真实接口信息，检查是否有错误或遗漏。如果发现检索不准，可以调整嵌入模型或优化文档切片策略；如果发现模型回答格式不对，可以调整提示词。

**3. 持续更新**
- **要做的工作**：当FEALPy版本更新、接口发生变化时，需要重新运行阶段一的提取脚本，更新向量数据库。可以把这个过程做成一个定时任务，或者在每次FEALPy发布新版本时手动触发。


### 总结：关键成功要素

| 要素 | 说明 |
|------|------|
| **知识库的完整性** | 覆盖 `bm` 下所有公共接口，并建立准确的后端映射 |
| **检索的准确性** | 通过语义检索而非关键词匹配，找到最相关的接口 |
| **回答的格式化** | 强制输出包含FEALPy接口、参数、对应后端接口和示例的标准化答案 |
| **多后端意识** | 在检索和生成时都要考虑用户指定的后端，避免混淆 |

按照这个流程，你可以在几天内搭建出一个可用的原型。核心工作量在阶段一的知识库构建上，一旦完成，后续的迭代和扩展都会非常顺畅。
